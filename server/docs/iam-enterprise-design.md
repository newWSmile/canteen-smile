# 企业级身份、组织与权限体系设计

> 状态：业务方案已确认，尚未进入数据库迁移、接口契约和业务编码阶段。
>
> 本文只定义已经讨论确认的领域边界、规则和安全约束，不代表已经存在任何 REST 接口、数据库表或权限编码。

## 1. 设计目标

本方案覆盖：

- 多租户客户隔离；
- 平台身份与租户身份隔离；
- 用户名密码登录；
- 手机号验证码登录及一个手机号绑定多个账号；
- 租户、机构类型、机构树和行政区域关联；
- 机构所有者、普通管理员、角色和用户；
- 菜单、按钮、接口和数据权限；
- 账号激活、密码重置、手机号绑定与恢复；
- 多设备会话、记住我和权限变更失效；
- 安全审计、跨服务可靠事件和服务间认证。

所有后端权限校验必须在服务端完成。前端隐藏菜单或按钮不能代替接口权限和数据权限校验。

## 2. 微服务边界

```text
Browser / App
      |
      v
smile-gateway
      |
      +----> smile-auth-service
      |        认证凭证、验证码、激活重置、Token、设备会话
      |
      +----> smile-iam-service
               租户、机构、用户、角色、菜单、权限、数据范围
```

### 2.1 smile-auth-service

只负责认证和会话：

- 用户名密码校验；
- 手机验证码生成和校验；
- 已验证手机号绑定；
- 密码摘要和密码历史；
- 账号激活链接；
- 密码重置链接；
- 登录失败、验证码错误和临时锁定；
- Token、设备会话和记住我；
- 一次性平台恢复码；
- Auth 领域安全审计。

Auth 只能通过 IAM Client 查询账号、租户、机构、角色和授权版本，不得直接访问 IAM 数据库。

### 2.2 smile-iam-service

负责身份与访问管理：

- 租户生命周期；
- 行政区域关联；
- 机构类型模板副本和允许挂载关系；
- 实际机构树；
- 平台身份和租户账号基本信息；
- 机构所有者；
- 角色、用户角色关系；
- 菜单、按钮、接口权限资源；
- 租户功能停用和菜单隐藏；
- 默认数据范围和业务模块覆盖范围；
- 账号、角色、机构及租户授权版本；
- IAM 管理审计。

### 2.3 数据所有权

- IAM 是 `accountId`、用户名、租户、机构、账号状态、角色和权限的唯一数据源。
- Auth 只使用 `accountId` 关联认证凭证，不复制并篡改 IAM 主数据。
- 两个服务使用独立 PostgreSQL 数据库；本地可以暂时使用同一个数据库账号，生产环境必须使用独立最小权限账号。
- 禁止跨数据库查询、跨服务外键、共享 Mapper 或共享 Entity。
- 主键统一使用 PostgreSQL sequence + `bigint`。

## 3. 租户与平台身份

### 3.1 租户定义

租户是客户和数据隔离边界，不等同于行政区域。租户可以关联行政区域，但两个租户可以关联同一个城市，单个租户未来也可以服务跨区域客户。

租户数据必须通过 `tenantId` 强制隔离。角色数据范围的并集永远不能突破租户边界。

### 3.2 租户状态

```text
待初始化 -> 正常 -> 暂停 / 已到期 / 注销
```

- 待初始化：根机构、所有者或基础配置尚未完成；
- 正常：允许使用；
- 暂停：平台手动暂停，可恢复；
- 已到期：合同或服务期限到期，可续期恢复；
- 注销：不可恢复。

暂停、到期或注销时提升租户安全版本，使全部租户会话失效并禁止重新登录。恢复后旧会话不恢复，用户必须重新登录。

### 3.3 租户初始化

平台超级管理员创建租户时同步完成：

1. 创建永久唯一租户标识；
2. 关联可选行政区域；
3. 创建租户根机构；
4. 复制平台默认机构类型和允许关系模板；
5. 初始化租户菜单配置；
6. 创建租户根机构首位所有者待激活账号。

租户名称允许修改，稳定租户标识不能修改或复用。只有从未激活且没有产生数据的错误租户可以物理删除。

### 3.4 平台超级管理员

- 使用独立平台管理入口；
- 不属于任何租户或机构；
- 不绑定租户角色；
- 当前阶段普通登录使用用户名和密码直接建立设备会话；
- 后续可仅对异常设备、高风险登录或敏感操作启用手机验证码二次验证；
- 手机不可用的受控恢复场景中，一次性恢复码可以替代短信验证码；
- 密码也遗忘时，通过专门恢复流程使用恢复码设置新密码；
- 平台应急查看或恢复租户必须再认证、填写原因并记录高等级审计。

恢复码只展示一次，服务端只保存摘要，每个恢复码只能使用一次；普通用户名密码登录不得要求或消费恢复码。重新生成整组恢复码后，旧恢复码全部失效。密码摘要统一采用 Argon2id；当前 `ARGON2ID_V1` 参数为 16 字节盐、32 字节摘要、并行度 1、64 MiB 内存和 3 次迭代，后续参数升级必须保留算法版本并渐进迁移。

## 4. 机构模型

### 4.1 机构类型

平台提供默认模板：

```text
国家 -> 省 -> 市 -> 区域 -> 中心校 -> 学校 -> 食堂
```

该模板只用于初始化，不构成固定层级。每个租户获得独立副本，只有租户根机构所有者可以维护本租户的机构类型和允许关系。

允许关系是有向无环关系，例如：

```text
市 -> 区县
市 -> 中心校
市 -> 学校
区县 -> 中心校
区县 -> 学校
中心校 -> 学校
学校 -> 食堂
```

必须防止类型关系环和实际机构树环。

### 4.2 机构类型生命周期

- 未使用类型允许删除；
- 已使用类型不能直接删除，只能停用；
- 停用后现有机构保留，禁止新建该类型机构或将其他机构调整为该类型；
- 类型稳定标识发布后不能复用于其他含义；
- 类型名称和显示顺序允许修改并保留审计。

### 4.3 实际机构树

- 实际机构只有一个直接父机构；
- 深度不固定；
- 机构业务编码在租户内永久唯一，原则上不可修改；
- 同一父机构下机构名称唯一，不同父机构允许同名；
- 机构可以关联一个行政区域，行政区域不参与机构父子关系；
- 机构可以在同一租户内迁移到另一个合法父机构；
- 账号禁止直接更换所属机构，需要新机构身份时创建新账号。

### 4.4 机构类型调整和迁移

修改机构类型或父机构时必须校验：

- 新父机构属于同一租户；
- 新的父子类型关系被允许；
- 新类型允许当前所有子机构类型；
- 不能移动到自身或自身下级；
- 不形成循环；
- 数据权限和业务约束仍然成立。

调整完成后提升机构路径或权限版本，使受影响会话重新登录，并记录调整前后的父机构、类型和操作者。

大机构迁移必须异步、分页处理，禁止长期占用 Web 请求线程或一次加载全部下级机构。

### 4.5 机构状态

- 正常：允许使用；
- 停用：可恢复，禁止机构账号登录；
- 已删除：只适用于从未产生用户、角色、下级机构及业务数据的空机构。

父机构停用后，所有下级机构继承实际停用状态，但不修改子机构自身状态。父机构恢复后，原本正常的子机构自动恢复；单独停用的子机构仍保持停用。

## 5. 用户账号与身份

### 5.1 账号归属

- 租户账号只能属于一个租户、一个机构；
- 同一自然人需要不同机构身份时创建不同用户名；
- 不同账号可以绑定同一个手机号；
- 同一手机号也可以在同一机构绑定多个账号；
- 每个可用账号必须拥有至少一个有效角色；
- 平台身份与租户身份严格区分。

### 5.2 用户名

- 全平台唯一且不区分大小写；
- 允许修改，但修改需要敏感操作再认证；
- 所有曾用用户名永久保留，不能被其他账号复用；
- 旧用户名不能继续登录；
- 修改用户名后全部设备会话失效；
- 注销账号的当前用户名和历史用户名继续永久占用。

### 5.3 显示名称与工号

- 显示名称非必填；
- 显示名称为空时由接口或前端展示当前用户名，不重复落库存储默认值；
- 工号可选，在同一租户和机构内唯一；
- 注销账号的工号永久保留，不能复用；
- 工号不作为登录凭证。

### 5.4 账号有效期

后台提供：

```text
长期有效
指定生效时间和到期时间
```

指定有效期尚未开始时可以完成激活，但不能进入业务系统。到期后全部设备下线并禁止登录；管理员延长有效期后可以恢复。角色绑定不单独设置有效期。

### 5.5 账号状态

- 待激活；
- 正常；
- 密码登录临时锁定；
- 待重置密码；
- 管理员停用；
- 注销。

管理员停用可恢复，注销不可恢复。密码登录临时锁定期间允许通过已验证手机号登录或找回密码。短信账号列表只返回当前可以通过短信进入登录流程的账号。

## 6. 机构所有者和角色

### 6.1 机构所有者

每个机构有且只有一个有效机构所有者，可以存在多个普通管理员。

机构所有者：

- 拥有租户当前启用的全部功能权限；
- 新增平台权限后自动获得；
- 业务数据范围为本机构及下级；
- 日常用户和角色管理只限本机构；
- 可以重置同机构普通用户和普通管理员；
- 不能跨租户或操作上级机构；
- 不能被普通管理员修改、停用或删除。

机构创建时只自动创建受保护的“机构所有者”角色，不初始化管理员、普通用户或只读用户等业务角色。所有权只能通过受控转让更换，转让必须再认证、填写原因并在单个本地事务内保证唯一所有者。

### 6.2 自定义角色

- 由机构自行创建；
- 角色名称只要求在本机构内唯一；
- 同一机构可以创建多个角色；
- 同一账号可以绑定多个角色；
- 功能权限和数据权限均取有效角色并集；
- 角色稳定标识和历史 ID 永久保留；
- 删除后的角色名称允许在同机构重新使用，新角色不能继承旧角色历史；
- 角色不设置独立生效时间和到期时间。

普通管理员创建或修改角色时：

```text
可分配功能权限 <= 管理员自己的功能权限
可分配数据范围 <= 管理员自己的数据范围
目标机构 = 管理员日常管理的本机构
```

机构所有者可以分配租户当前启用的全部功能权限，但不能把机构所有者身份当作普通角色授予。

### 6.3 角色变更会话策略

以下变化都使受影响账号全部设备会话失效并要求重新登录：

- 角色停用或删除；
- 删除功能权限；
- 新增功能权限；
- 缩小或扩大数据范围；
- 给用户新增或移除角色。

实现时使用用户、角色和租户授权版本完成逻辑失效，禁止循环删除大量 Redis Key。

## 7. 菜单与功能权限

### 7.1 权限资源归属

菜单、按钮和接口权限由平台开发和平台管理端维护。租户和机构只能分配已经发布的权限资源，不能创建权限编码。

业务操作权限同时约束前端按钮和后端接口，后端是最终校验方。一个业务权限可以对应多个真实后端接口，但不能用前端隐藏代替后端授权。

### 7.2 权限标识生命周期

- 未发布且未使用的权限可以修改或删除；
- 已发布权限的稳定标识永久保留；
- 已发布权限允许废弃；
- 已废弃标识不能复用于另一种业务含义；
- 新业务含义必须发布新权限；
- 名称、描述和展示信息可以在不改变业务含义时修改；
- 历史角色授权和审计必须能够按当时含义追溯。

### 7.3 租户功能和菜单显示

必须区分：

| 控制层 | 作用 | 是否影响接口权限 |
| --- | --- | --- |
| 租户停用功能 | 整个租户不可使用 | 是 |
| 租户隐藏菜单 | 租户导航不显示 | 否 |
| 用户个人隐藏 | 当前账号个人偏好 | 否 |

父菜单隐藏时全部子菜单自动隐藏。租户角色原授权关系保留，重新显示或启用后不需要重新授权。

租户设置和菜单管理入口不能被租户自己隐藏或停用，确保租户根机构所有者可以恢复配置。

## 8. 数据权限

### 8.1 数据范围类型

- 本人；
- 本机构；
- 本机构及下级；
- 指定机构本身；
- 指定机构及下级；
- 租户全部。

指定机构只能选择同租户且在授权人有效范围内的机构。

### 8.2 默认范围和模块覆盖

每个角色包含一个默认数据范围，并允许由平台定义的业务模块配置覆盖范围：

```text
模块有效范围 = 模块覆盖范围（存在时）否则角色默认范围
用户模块范围 = 所有有效角色模块范围的并集
最终 SQL = tenantId 强制条件 AND 模块数据权限条件
```

模块没有明确数据归属字段时不得猜测。各业务模块必须确认自己的归属字段，通常可以是 `created_by`，也可以是负责人、审核人或业务所属人。

### 8.3 SQL 强制要求

- 数据权限必须下推 SQL；
- 禁止查询全量数据后在 Java 中过滤；
- 禁止使用前端传入的组织范围作为可信权限条件；
- 列表必须分页并限制页大小；
- 机构下级范围使用可索引的机构路径或等价方案；
- 多角色并集必须合并和去重条件，避免逐角色循环查询数据库。

## 9. 登录、手机号和账号选择

### 9.1 用户名密码登录

用户名全平台唯一，因此无需额外输入租户编码。登录成功前必须校验：

- 租户实际状态；
- 账号状态及有效期；
- 机构及祖先实际状态；
- 密码和失败锁定；
- 至少一个有效角色；
- 授权版本。

### 9.2 手机验证码登录

手机号只是一种已验证登录凭证，不是账号唯一标识。

```text
手机号 + 验证码
        ↓
Auth 校验成功
        ↓
生成短期一次性账号选择凭证
        ↓
批量查询 IAM 中可登录账号
        ↓
一个账号：直接选择该账号
多个账号：展示租户、机构、用户名及最近登录信息
        ↓
用户选择账号
        ↓
选择凭证失效
        ↓
签发正式会话
```

验证码验证前禁止泄露手机号绑定了哪些账号。最近登录记录精确到账号，而不是只记录机构。

### 9.3 手机号绑定和换绑

- 管理员录入的手机号是待验证信息；
- 用户完成验证码校验后才成为正式绑定；
- 同一手机号可以绑定多个账号；
- 正常换绑需要验证旧凭证或当前密码，再验证新手机号；
- 旧手机号不可用时由授权管理员发起恢复，用户仍必须验证新手机号；
- 管理员不能把未验证手机号直接设置为已绑定；
- 换绑成功后全部设备会话失效。

## 10. 激活和密码恢复

### 10.1 新账号激活

管理员创建账号时必须分配至少一个角色，账号进入待激活状态。管理员不知道最终密码。

- 有可用手机号：用户通过 5 分钟短信验证码验证手机号并设置密码；
- 无手机号或无法收信：管理员生成一次性激活链接线下交付；
- 激活链接默认 24 小时有效、只使用一次、服务端只保存摘要；
- 重新生成后旧链接失效；
- 激活链接不能访问业务接口。

### 10.2 自助找回密码

用户通过已验证手机号完成验证码校验后设置新密码。成功后旧密码和全部设备会话失效。

### 10.3 管理员发起密码重置

同机构管理员可以在角色明确拥有重置权限时重置普通用户。普通管理员默认不能重置同机构其他管理员；机构所有者可以重置同机构所有账号。被明确授权的上级机构管理员可以搜索权限范围内的下级账号并发起恢复。

管理员需要选择：

- 手机号 + 验证码模式；
- 一次性重置链接模式。

一次性重置链接用于无手机号、手机号失效、无法收信或短信服务异常等场景：

- 管理员必须再认证并填写原因；
- 链接只展示一次；
- 默认 30 分钟有效；
- 使用一次后失效；
- 新链接使旧链接失效；
- 服务端只保存摘要；
- 链接不能直接登录业务系统；
- 禁止写入日志和审计明文。

发起重置后目标账号立即进入待重置状态，所有会话失效，旧密码和短信登录均不能进入业务系统，只允许完成密码重置。链接过期后账号仍保持待重置，必须重新发起。

## 11. 密码、验证码和登录防护

### 11.1 默认密码策略

- 最少 8 位；
- 至少满足数字、大写字母、小写字母、特殊字符中的 3 类；
- 禁止常见弱密码；
- 禁止包含完整用户名或手机号；
- 最近 5 次密码不能重复；
- 普通租户默认不强制定期修改；
- 租户可以启用密码到期策略并提高安全要求；
- 密码只保存不可逆强哈希摘要。

### 11.2 密码失败保护

- 连续失败 3 次要求图形验证码；
- 连续失败 5 次锁定密码登录 15 分钟；
- 成功登录后清空连续失败计数；
- 同时按账号、IP 和设备限流；
- 响应不得泄露账号是否存在。

### 11.3 短信验证码

- 5 分钟有效；
- 同一手机号 60 秒内不能重复发送；
- 同一验证码只能成功使用一次；
- 验证错误 5 次后失效；
- 按手机号、IP 和设备设置小时及每日限流；
- 验证码、短信密钥和完整手机号不得写入普通日志。

## 12. 设备会话

### 12.1 租户配置

租户后台可以配置：

- 是否允许同账号多设备同时登录；
- 最大有效设备数，默认 5；
- 是否允许记住我；
- 普通会话空闲时间，默认 2 小时；
- 普通会话最长时间，默认 7 天；
- 记住我空闲时间，默认 7 天；
- 记住我最长时间，默认 30 天。

租户只能在平台安全上限内调整，不能配置永久会话。

租户禁止并发登录时，新登录成功并下线全部旧设备。允许并发时每次设备登录生成独立会话，不同设备不能共享同一个 Token。

### 12.2 会话管理

用户可以查看设备类型、浏览器、登录 IP、登录时间、最近活跃时间和登录方式，并下线指定设备或除当前设备外的全部设备。

以下变化使全部设备会话失效：

- 修改密码或用户名；
- 管理员重置密码；
- 手机号换绑；
- 账号停用或注销；
- 账号到期；
- 角色或授权变化；
- 机构或祖先停用；
- 租户暂停、到期或注销。

## 13. 权限快照和最终校验

正式会话固定：

```text
身份类型
tenantId（平台身份无租户）
organizationId
accountId
角色集合
用户授权版本
角色授权版本
机构路径版本
租户安全版本
```

权限快照包含功能权限和按业务模块计算的数据范围。IAM 临时不可用时允许使用已经验证且版本有效的快照；快照缺失、签名失败或版本无法确认时拒绝访问。

Gateway 只做登录和版本粗校验。每个业务服务必须执行最终接口权限、组织权限和 SQL 数据权限校验。

## 14. 内部服务安全

Auth 与 IAM 当前使用显式 REST Client 和静态服务地址，未来接入 Nacos 后只替换地址发现，不改变契约和认证边界。

内部接口必须：

- 不通过 Gateway 暴露；
- 只允许内部网络访问；
- 使用 HMAC 请求签名；
- 包含时间戳、随机数和事件 ID；
- 校验时间窗口并防止重放；
- 密钥只从环境变量或密钥服务读取；
- 设置连接、读取超时和有限重试；
- 只对幂等请求重试；
- 记录调用服务，不记录签名密钥。

## 15. 可靠跨服务事件

关键权限和状态变化使用“本地事件表 + 可重试投递”：

```text
IAM 本地事务
├─ 修改业务数据
└─ 写入待投递事件
        ↓
事务提交后调用 Auth
        ↓
成功：完成
失败：保留并由 XXL-JOB 分页重试
```

要求：

- 每个事件有全局唯一事件 ID；
- 消费者按事件 ID 幂等；
- 事件不包含密码、验证码、Token、签名密钥和完整链接；
- 重试使用分页和退避策略；
- 禁止一次加载全部事件；
- 超过告警阈值后进入人工处理；
- 后续接入消息队列时，本地事件表继续作为可靠事件源。

## 16. 审计

### 16.1 Auth 安全审计

- 登录成功和失败；
- 验证码发送和校验；
- 密码修改和重置；
- 手机绑定、解绑和换绑；
- 激活及重置链接生成和使用；
- 设备登录和强制下线；
- 账号锁定和解锁；
- 内部签名验证失败。

### 16.2 IAM 管理审计

- 租户状态变化；
- 机构新增、迁移、停用和删除；
- 机构类型和允许关系变化；
- 机构所有权转让；
- 用户新增、停用和注销；
- 用户名修改；
- 角色和授权变化；
- 菜单隐藏和功能停用；
- 数据范围变化；
- 管理员密码重置；
- 平台应急恢复和查看租户审计。

### 16.3 审计规则

- 审计日志只追加，普通业务不得修改；
- 平台最低保留 180 天，租户可以配置更长；
- 租户根机构所有者可以查看本租户全部管理和安全审计；
- 敏感字段必须脱敏；
- 禁止记录密码、验证码、Token、完整手机号、签名密钥和完整一次性链接；
- 记录操作者、目标、租户、机构、IP、设备、时间、TraceId、结果和非敏感差异；
- 列表必须分页，大规模导出必须异步。

以下操作要求填写原因并完成管理员再认证，但当前不要求多人审批：

- 设置或转让机构所有者；
- 分配租户全部或本机构及下级数据范围；
- 给管理员增加用户、角色或密码重置能力；
- 修改租户功能和菜单配置；
- 修改机构类型允许关系；
- 平台查看租户安全审计；
- 生成平台恢复码。

## 17. 数据建模约束

IAM 至少需要覆盖以下逻辑聚合，具体表名和字段在数据库设计阶段确认：

- 平台身份；
- 租户及租户配置；
- 行政区域引用；
- 机构类型和类型允许关系；
- 机构、机构名称历史和机构路径；
- 租户账号、用户名历史和工号保留记录；
- 机构所有权；
- 角色、用户角色关系；
- 权限资源、角色权限关系；
- 租户功能配置和菜单显示配置；
- 角色默认数据范围和模块覆盖范围；
- 指定机构数据范围；
- 授权版本；
- IAM 审计和本地事件。

Auth 至少需要覆盖以下逻辑聚合：

- 账号认证凭证；
- 密码历史；
- 手机号绑定；
- 短信验证码及发送限制；
- 激活凭证；
- 密码重置凭证；
- 平台恢复码；
- 设备会话；
- 登录失败和锁定；
- Auth 审计及事件消费幂等记录。

核心业务表必须包含 `created_by`、`created_time`、`updated_by`、`updated_time` 和 `is_deleted`。Entity 只映射本服务表，接口不得直接使用 Entity。

## 18. 实施前仍需确认的技术项

已确认数据库变更当前使用根目录 `sql` 的人工版本脚本，暂不引入 Flyway；未来接入迁移工具时必须先制定人工基线接管方案。

以下内容尚未形成真实契约，编码前必须继续确认，禁止猜测：

- 真实 REST 路径、请求 DTO、响应 VO 和错误码；
- 真实菜单、按钮、接口权限标识；
- IAM 服务端口和各环境静态地址；
- 两个 PostgreSQL 数据库的真实名称和账号；
- 密码哈希组件和成本参数；
- 图形验证码实现；
- 短信服务供应商及 Client 契约；
- HMAC 签名算法、签名串、时间窗口、Nonce 存储和密钥轮换；
- 权限快照格式、缓存 Key、TTL 和签名方式；
- 各业务模块编码和“本人”数据归属字段；
- XXL-JOB 执行器、事件重试批次和告警阈值；
- 平台默认机构类型模板的最终初始化数据。

这些技术项确认前，只能继续做逻辑模型、ER 关系和接口草案，不能伪造可运行接口或数据库字段。
