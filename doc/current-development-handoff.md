## 1. 固定技术与运行约定

- 前端是 Vue 3 + Vite + TypeScript 的 pnpm workspace，固定 Node.js `20.19.0`、pnpm `10.34.5`，禁止 Vue 2。
- 三个前端应用：平台管理端 `5173`、租户管理端 `5174`、租户业务端 `5175`；开发服务器监听 `0.0.0.0`，默认经 `/api` 代理 Gateway `8080`。
- 后端是 Java 17、Spring Boot 3.5.16、Maven 多模块微服务：Gateway `8080`、Auth `8081`、IAM `8082`。PostgreSQL 按服务独立数据库，Redis 使用 Cluster。
- 外部请求统一进入 Gateway；Gateway 到 Auth/IAM 当前使用静态地址，内部调用使用显式 Client、版本化 DTO 和 HMAC，后续再接 Nacos。
- 本地真实地址和凭据只放各服务未提交的 `application-local.yml`，启动配置使用 `SPRING_PROFILES_ACTIVE=local`。
- PostgreSQL 脚本只放根目录 `sql/<service>/{ddl,dml}`，当前不使用 Flyway；脚本人工执行后在 `sql/CHANGELOG.md` 标记 `EXECUTED` 并永久冻结。
- 前端开发 HTTPS 使用 `cd web && pnpm https:setup` 生成本地证书，再执行 `pnpm dev:platform`、`pnpm dev:tenant-admin`、`pnpm dev:tenant-portal`。密码加密依赖浏览器安全上下文，局域网 HTTP 不能视为正式解决方案。

## 2. 已确认的 IAM 核心规则

- 多租户边界是“客户”，行政区域只作关联。当前业务通常以市级客户为一个租户。
- 机构类型和允许的父子关系可配置；默认模板复制给租户后独立维护。机构不是固定行政链，但必须阻止环、非法反向关系和跨租户关联。
- 一个账号只属于一个机构；同一手机号可以绑定多个账号，手机号登录在多候选时选择账号，并显示最近登录信息。
- 用户名全平台大小写不敏感唯一，可修改；现用及曾用用户名永久占用。工号机构内唯一，注销后永久保留。
- 一个账号可有多个角色，功能权限与数据权限均取并集。数据范围包括本人、本机构、本机构及下级、指定机构、租户全部，并支持角色默认范围加业务模块覆盖。
- 菜单和按钮由平台发布，租户只能分配；“隐藏菜单”和“停用功能”是两个不同配置。权限编码发布后永久保留且禁止复用。
- 每个机构只有一个机构所有者，可有多个普通管理员。所有者受系统保护，日常用户和角色管理默认只限本机构。
- 敏感授权和生命周期操作必须填写原因并完成管理员再认证，暂不要求多人审批。
- 角色停用、删除、权限缩小、数据范围缩小、账号或租户状态收紧，必须让受影响账号全部设备重新登录。
- 租户可配置并发登录，默认最多 5 台设备；普通会话空闲 2 小时、最长 7 天，记住我空闲 7 天、最长 30 天。
- 密码使用 Argon2id；密码传输使用短期公钥、`keyId + nonce + timestamp` 与 RSA-OAEP/AES-GCM，密钥默认按约 30 天轮换，挑战仍一次性消费。
- 审计记录真实操作者、对象、中文动作快照、链路、耗时和完整可信客户端 IP。登录等认证后才知道主体的场景使用 `AuditLogUtils`，普通登录后业务使用 `@AuditOperation`。

## 3. 当前真实落地范围

### 平台管理端

- 首位平台超级管理员一次性引导、Argon2id 凭证、恢复码和独立平台身份登录。
- 机构类型模板版本发布。
- 五步创建租户、根机构与首位所有者同步初始化、所有者激活/找回。
- 租户列表和租户名称修改、暂停、恢复、不可恢复注销；状态收紧提升安全版本并写账号级 Outbox。
- 权限资源草稿、发布和废弃；短信列表、短信设置、短信安全；平台审计。

### 租户管理端

- 密码登录、手机号验证码登录和多账号选择。
- 机构类型与关系、按需分页机构树、机构新增/修改/迁移/状态/空白机构删除。
- 角色 CRUD、功能权限整版分配、数据范围配置、所有者角色保护。
- 用户分页、创建待激活账号、编辑资料与有效期、分配角色、停用/恢复/注销、激活与密码恢复。
- 手机号绑定、换绑、解绑、自助找回密码；登录设备查询和单设备/其它全部设备下线。
- 租户安全策略、中文审计页面；侧栏详情不遮挡列表且可直接切换行。

### Auth、可靠事件与审计

- 短信采用 `SmsClient` 策略；本地 `LOCAL_DATABASE_LOG` 只写数据库和安全日志，真实厂商待 SDK 契约确认后新增策略实现。
- 验证码按 `LOGIN`、`MOBILE_BIND` 等用途隔离，5 分钟有效、错误 5 次失效，并具备手机号/IP/设备多维限流。
- IAM Outbox 由 XXL-JOB 的 `iamOutboxDeliveryJob` 有界投递；Auth 按事件 ID 和载荷摘要幂等消费并真正使全部设备会话失效。
- `smile-audit-starter` 已提供注解驱动异步审计；IAM/Auth 各自监听并写入本服务数据库，未来可替换为 MQ 发布器。
- 三个前端应用已有固定主布局、路由内打开页面、面包屑、可折叠菜单，以及统一的查询栏、列表、弹窗和反馈规范。

租户业务端目前主要完成独立应用骨架、认证和共享安全能力；具体食堂业务模块尚未取得真实字段和接口契约，禁止提前伪造。
